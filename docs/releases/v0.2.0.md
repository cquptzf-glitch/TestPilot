# TestPilot v0.2.0

发布日期：2026-10-23

这是 TestPilot 的首个 GitHub Release。v0.2.0 把项目从功能原型推进到一条可持续迭代的自动化测试主链：用例来源、AI/Agent 辅助生成、人审、确定性执行、失败证据、知识闭环与桌面工作流已经连通。

## 主要更新

### 日常测试主流程
- “开始测试”统一承载：选择用例 → 必要 DSL 生成 → 人工审核 → 执行前确认 → 自动执行 → RunDetail。
- 独立 DSL 审核完成后可直接进入执行前确认，减少重复选用例和重复确认。
- 执行异常先确认是否已经产生 run；RPC 断线不再直接诱导重复执行。
- RunDetail 区分运行级异常、中止、证据不完整、普通用例失败与仅禅道回写失败，并给出对应恢复动作。

### 自动化探索
- UIA + Vision 双模式探索。
- 支持点击、输入、选择、读取、断言、右键、滚动、拖拽、keypress、截图差异等动作。
- 支持多会话、历史编辑/重跑、截图缩放/平移/元素反查、视觉框选与模板保存。
- 探索路径固化为 DSL 后必须进入人审，临时 element_index 不进入正式回归 DSL。

### Agent / SVN 变更分析
- SVN 工作副本 / revision 变更可通过 Pi Agent 生成测试意图与本地用例草稿。
- Agent 的文件、SVN、用例读取全部通过 TestPilot 主进程 RPC 执行，无直接文件系统或 Shell 权限。
- 增加 workspace capability token、工具审计、grounding evidence、snapshot drift 防护、关联用例 semantic token 与原子批量持久化。
- 相同变更与测试语义支持幂等复用，并提供轻量 generation_run_id。

### 执行与可靠性
- 确定性 DSL 是正式回归主链，LLM/Agent 不参与正常执行决策。
- UIA / Vision capability-aware fallback；真正执行动作失败后仍保留副作用保护。
- 失败用例可按策略复跑，保留每次尝试轨迹与首次失败证据。
- 修复 run.progress 事件契约、Router 样本重复计数、任务配置优先级和执行参数边界。
- 任务创建、执行、远端禅道测试单补偿路径具备更严格的幂等与 crash fail-closed 保护。

### 禅道与结果分析
- 支持按产品 watermark 的真正增量同步，以及显式全量校准。
- RunDetail 提供 result-first 概览、失败轨迹直达、运行对比、稳定性、驱动降级、环境兼容矩阵和知识库上下文。
- 禅道远端创建/回写失败与本地执行解耦；本地结果不会因为远端增强链异常而丢失。

### Windows 桌面发行
- Tauri 2 + React 桌面壳。
- Python 引擎以 PyInstaller onedir sidecar 随安装包分发，目标机器无需预装 Python / Node。
- Release workflow 在发布前重新执行 Ruff、全量 Pytest、sidecar 自检、打包静态预检和 NSIS 构建。
- GitHub Release 附带 NSIS 安装包与 SHA256SUMS.txt。

## 当前边界

以下真实环境验证仍不作为当前功能开发阻塞项：
- Qt Widgets / Qt Quick 真机 UIA 回归；
- 125% / 150% / 200% DPI 与多屏/负坐标验证；
- 真设备 + 模拟器联合 smoke；
- 公司 SVN + 实际 Pi provider/model 的端到端 smoke；
- 干净 Windows 机器安装/卸载验证。

## 升级

v0.2.0 继续使用现有幂等数据库迁移逻辑。建议升级前保留 TestPilot 用户数据目录备份，再安装新版覆盖使用。
