# UI 操作流和用例批量分析修复（2026-10-16）

## 已确认的断点

- 新拉取用例为 synced + draft + 0 步，行尾分析按钮却只对 stale/conflict 显示，无法在用例库继续生成 DSL。
- 原批量操作只包含远端变更，不包含初次拉取的空 DSL，也不接受勾选的用例列表。
- 分析任务完成后没有逐条结果及审核队列；切页时新页面不会自动刷新结果。
- 开发预览缺少 job.start/status/cancel 实现，真实桌面已有的后台任务无法在预览中操作。
- 原批量解析把 AbortRequested 当一般业务失败吞掉；最后一条取消可能被报告为已完成。
- 审核页异步导出没有取消旧响应，快速切换用例可能加载前一条的草稿。

## 完成的修改

1. 用例库显示“拉取 → 分析 → 审核 → 创建任务”的流程，拉取、筛选和批量操作分区。
2. 提供全选当前筛选结果、分析所选生成 DSL、分析当前待生成/待更新；每行始终提供分析/审核或原文入口。
3. case.parse 接受 caseIds 字符串列表，去重保序；每批最多 500 条，拒绝空列表、非法类型和歧义范围。
4. 批量进度显示总数、已处理、当前用例；逐条保存，失败后继续，取消保留成功结果。失败用例可单独查看并重试。
5. 全局任务栏跨页保留，任务结束触发列表与详情刷新；后台任务期间禁止重复发起。
6. 结果进入逐条审核队列，支持上一条、下一条及未保存修改的切换提示；返回用例库保留队列选择，审核通过后可创建测试任务。
7. 空 DSL 不可审核通过；未审核用例不可由批量工具栏创建任务。AI 结果仍需人工逐条核对后生效。
8. 开发预览补齐后台任务和批量分析演示，继续使用模拟数据，未将其作为真实模型验证证据。

## 单页简化操作流（用户继续要求后完成）

默认首页改为“开始测试”，三步在同一页面完成：
- 选择用例：可从禅道拉取并自动选中，也可选已有用例。需要时填写窗口标题或程序路径。
- 分析与确认：对缺少 DSL 或远端已更新的所选用例批量生成。已生成的草稿直接审核；确认后自动进入下一条。
- 执行测试：已审核用例直接执行，自动创建任务并进入进度/报告。无需手工创建方案和任务。禅道同步、驱动选择收起为可选设置，默认本地运行。

为防止“有点击/输入步骤但未附加窗口”的执行失败，提供被测软件目标输入。case.parse 的 appTarget 会写入待审核 app.launch 步骤，审核页可见；不会自动激活草稿。执行前检查 UI 动作之前有有效的启动/附加窗口步骤，缺失时给出具体修复入口。

执行创建任务后先保存 ID；执行请求失败重试复用该任务，避免反复建单。后台取消信号在 RPC 分发处保持原异常，避免被误包装为失败。

预览验证：从首页拉取两条用例、填写窗口标题（包含括号，正则已转义）、批量生成、逐条确认自动前进、自动进入执行准备、一键创建任务执行、自动进入进度页全部实际点击通过。预览仅为模拟数据。
